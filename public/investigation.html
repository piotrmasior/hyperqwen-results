01 / WHAT ACTUALLY PASSED

Review changed the outcome.

Exact archived artifacts were re-executed on November 6. The model authored candidate implementations and edits; a separate supervising agent supplied checks and review.

100 independent development checks · 156 generated tests · 12 reused regression checks · 9 SQL controls. These categories must not be combined into a count of independent tests.

The first held-out result stays 11/12.

Migration initially failed a calendar case. Repairing it brought the reused suite to 12/12; that is regression evidence. All 24 Node suites and the incident SQL controls passed in the final archived replay.

Repairs addressed ownership fencing, stable payment identity, expiry boundaries, unknown-money holds, refunds, backfill faults and contiguous offsets. Runbooks needed separate review.

Acceptance rules stayed intact.

Tests that removed assertions or normalized a defect were rejected. No manually corrected candidate implementation is credited to the model. Failed attempts remain in the cost ledger.

Limits remain: migration can hold retired-owner rows without a general closure API; incident unknowns need authoritative evidence; ingestion still needs verified identities and real broker integration. This is not production certification.

02 / THE FRESH-RUN CHECK

Compilation was not enough.

A prospectively fixed workflow allowed one initial generation and up to two replacements per artifact. No successful previous answer or independent test source entered its prompts.

~120k source selection→Schema→Implementation→Tests: all four blocked→Runbook: not reached

31 calls · 416,489 output tokens · 55.56 minutes of request wall time. All 31 responses reported normal stop, including unfinished files. This workflow used source selection; it was not a 120k-input call at every stage.

PAYMENT

A thousandfold expiry error.

Milliseconds were supplied as SQL seconds. A 26-hour expired dispatch called the provider. Distinct opaque identifiers collided under colon concatenation; migration of populated legacy rows failed.

INCIDENT

Compiling code, broken takeover.

Default PostgreSQL BIGINT string decoding broke an expired claim takeover. A crash before storing the provider result reported zero unknown exposure instead of 1,800 cents.

MIGRATION

Ownership and ambiguity lost.

A retired-region request sent a payment after cutover. A lost response after simulated acceptance became definite failure instead of an ambiguous result.

INGESTION

A test can endorse the bug.

Repeated recovery credited 500 cents instead of 250. Generated tests expected that wrong amount and attempted to replace faulty frontier SQL. They were rejected as acceptance evidence.

Client limitations and earlier seeds

Seeds43/44 each produced zero complete packages, partly because the strict client rejected complete Markdown wrappers and could not repair missing files. Those are not eight fully assessed semantic failures. Seed45 accepted complete wrappers and checked prerequisites immediately.

Seed45 still restricted repairs to the current artifact. A test-stage failure could not repair an earlier schema or implementation. Ingestion's final test setup failed and canceled 24 tests; those are not 24 failed behavioral assertions. No runbook was generated. Future trials should allow dependency-aware repairs while preserving independent assertions and a frozen retry bound.

03 / NUMERICAL CONTROL

One EOS gap moved.
Quality did not follow.

Restore the q/k/v/o projections in 16 full-attention layers from official BF16. Verify 64 restored tensors and 1,830 unchanged tensors bit for bit.

EOS probability at a fixed prefix

Teacher-forced recomputation on identical token hashes and runtime: no MTP, eager, BF16 KV, FP32 state. Only the checkpoint changed. This is a next-token probability, not a quality score or a replay of original incremental-decode logits.

Both probes, with exact values

A narrow, reproducible signal.

Incident EOS fell from 56.0% to 13.3%, switching the top token to a continuation. Payment stayed near 24.5%. The incident result met the predeclared follow-up threshold; it does not establish a general fix.

Extra precision costs memory.

Tensor storage grew by 2.49 GB (2.32 GiB). Three 150k startup attempts failed on memory. A fourth started with eager execution, batch 512, one sequence, 96% GPU allocation and an explicit 5.8 GB KV cache.

Full 150k capacity, four original final requests

~120k input · 30k allowance · low reasoning · temperature 1 · seed42 · MTP3 · FP8 KV · FP16 state. Zero cached tokens or preemptions. Every response ended with normal EOS. Runtime and weights both changed, so this is not an isolated weights-only generation comparison.

The same three incident behavioral counterexamples still failed on verbatim extracted functions: each made one forbidden extra provider call. The other three packages failed source/completion review. Full-prefix probes in the combined runtime still gave 59.09% incident EOS; do not generalize the short-prefix 13.3% result to long generation.

04 / OTHER PATHS TESTED

No single switch solved it.

Normal final EOS and MTP remain enabled in the restored fast profile. No experimental configuration was promoted.

REASONING-BOUNDARY GUARD

An answer, still incorrect.

On the same 25,894 input tokens, an opt-in guard changed 10,453 tokens with no answer into 20,603 tokens with an answer. Semantic checks still failed. Five unit tests passed; normal final EOS was preserved. One matched pair is not a reliability estimate.

MODEL / CACHE / STATE

No all-four correctness fix.

Base weights, FP32 state, KV variants, MTP removal and shorter thinking budgets did not establish complete, correct engineering outputs. Head/embedding restoration and dense reconstruction did not explain the incident EOS gap.

UPSTREAM GSM8K CHECK

191 / 200 · 95.5%

The unmodified upstream math quality protocol passed at this level: thinking off, greedy, 768-token cap, 32 client threads. This is a different task and execution protocol from long engineering generation.

16,282 IS NOT A HARD LIMIT

Allowance remains unused.

Outputs exceeded 20k in other runs. Final EOS truncations occurred at varying lengths. Ignoring final EOS exposed control markers and was not adopted; increasing the allowance did not solve semantic defects.

What to test next: dependency-aware bounded repair with frozen independent checks; new held-out schedules after development; matched runtime controls for numerical hypotheses; separate runbook validation. These are proposed experiments, not measured improvements.
